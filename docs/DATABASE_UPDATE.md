# Обновление базы данных Pluschat

Основная база: MySQL `pluschat` на `localhost`. Обновление рассчитано на основной PHP-сервер; отдельный сайт для звонков не нужен.

## Перед обновлением

1. Сделайте резервную копию базы `pluschat` через панель хостинга/phpMyAdmin.
2. Убедитесь, что `confirm.php` с настройками не удалён. Новый `bootstrap.php` читает `config.php`, а если его нет — пытается прочитать `confirm.php`.
3. Обновите файлы проекта из репозитория.

## Существующая база

Запустите из корневой папки проекта через PHP CLI:

```sh
php database/migrate.php
```

Команда применяет неприменённые файлы `database/migrations/*.sql` по порядку и записывает их имена в `schema_migrations`. Этот скрипт намеренно не запускается через браузер. Не создавайте публичную ссылку на выполнение миграций.

Миграции, уже присутствующие в репозитории:
- `001_social_features.sql` — социальные функции;
- `002_chat_organization.sql` — папки/организация чатов;
- `003_stories.sql` — истории;
- `004_password_recovery.sql` — восстановление пароля;
- `005_message_hiding.sql` — скрытие сообщений;
- `006_mandatory_two_factor.sql` — таблицы 2FA;
- `007_private_profile_avatars.sql` — аватары/профиль;
- `009_calls_signaling.sql` — сигнализация аудио-/видеозвонков на основном сервере;
- `010_notification_settings.sql` — настройки уведомлений по категориям и режим предпросмотра.

Для новой пустой базы импортируйте `database/schema.sql`, затем выполните миграции через PHP CLI. Не импортируйте схему поверх существующей базы.

## Настройки подключения

Секреты подключения к MySQL и почте должны оставаться на хостинге, а не в GitHub. Если в `confirm.php` используются нестандартные имена переменных, `bootstrap.php` может потребовать дополнительной адаптации. Не отправляйте пароль БД или API-ключи в чат.

## Проверка после обновления

1. Проверьте результат команды: миграции должны отображаться как `APPLIED` или `SKIP`, без `ERROR`.
2. Проверьте API health endpoint: `https://xn--80avljg2a1c.xn--p1ai/api/v1/health`.
3. Отдельно проверьте email-код и ссылку восстановления пароля.
4. Проверьте звонки на двух устройствах: создание вызова, сигнализацию WebRTC, звук/видео и завершение. Наличие таблиц вызовов само по себе не означает, что Android WebRTC и TURN уже готовы.

Успешное выполнение миграций не доказывает, что email, звонки или все API-функции работают на живом хостинге; их нужно проверить отдельно.
