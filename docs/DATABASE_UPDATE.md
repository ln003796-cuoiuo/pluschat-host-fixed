# Обновление базы данных Pluschat

Основная база: MySQL `pluschat` на `localhost`. Обновление рассчитано на основной PHP-сервер; отдельные сайты для звонков или SMS не нужны.

## Перед обновлением

1. Сделайте резервную копию базы `pluschat` через панель хостинга/phpMyAdmin.
2. Убедитесь, что на сервере уже есть приватный файл `config.php` с правильным паролем БД. Не загружайте этот файл в GitHub.
3. Обновите файлы проекта из репозитория.

## Существующая база

Запустите из корневой папки проекта через PHP CLI:

```sh
php database/migrate.php
```

Команда применяет неприменённые файлы `database/migrations/*.sql` по порядку и записывает их имена в `schema_migrations`. Этот скрипт намеренно не запускается через браузер. Не создавайте публичную ссылку на выполнение миграций.

Миграции, уже присутствующие в репозитории:
- `001_social_features.sql` — социальные функции;
- `002_chat_organization.sql` — папки/организация чатов;
- `003_stories.sql` — истории;
- `004_password_recovery.sql` — восстановление пароля;
- `005_message_hiding.sql` — скрытие сообщений;
- `006_mandatory_two_factor.sql` — таблицы 2FA;
- `007_private_profile_avatars.sql` — аватары/профиль;
- `008_textbee_phone_verification.sql` — телефон и SMS-коды;
- `009_calls_signaling.sql` — сигнализация аудио-/видеозвонков на основном сервере.

Для новой, ещё пустой базы установщик использует `database/schema.sql`, затем применяет миграции и проверяет обязательные таблицы.

## TextBee

TextBee API key и device ID — настройки сервера, а не поля MySQL. Храните их только в приватном `config.php` или переменных окружения хостинга:
- `PLUSCHAT_TEXTBEE_API_KEY`
- `PLUSCHAT_TEXTBEE_DEVICE_ID`

Не помещайте секреты в `config.example.php`, SQL, Android APK или публичный GitHub-репозиторий. API key передаётся сервером в заголовке `x-api-key`; запрос к TextBee выполняется сервером по HTTPS.

## Проверка после обновления

1. Проверьте результат команды: миграции должны отображаться как `APPLIED` или `SKIP`, без `ERROR`.
2. Проверьте API health endpoint: `https://xn--80avljg2a1c.xn--p1ai/api/v1/health`.
3. Проверьте реальную отправку SMS на свой номер и подтверждение телефона.
4. Отдельно проверьте email-код и ссылку восстановления пароля.
5. Проверьте звонки на двух устройствах: создание вызова, сигнализацию WebRTC, звук/видео и завершение. Наличие таблиц вызовов само по себе не означает, что Android WebRTC и TURN уже готовы.

Успешное выполнение миграций не доказывает, что SMS, email, звонки или все API-функции работают на живом хостинге; их нужно проверить отдельно.
