# Pluschat Host Fixed — исправление авторизации без номера телефона

Этот репозиторий — **набор файлов-замен**, а не полная копия сервера. Он не изменяет исходный `ln003796-cuoiuo/pluschat-host`.

## Что исправлено

- Регистрация больше не требует номер телефона и не отправляет SMS.
- Регистрация сохраняет email-код подтверждения; код хранится в БД в виде хеша.
- Вход работает по email или нику и паролю без проверки номера телефона.
- Bearer-токены больше не отклоняются только из-за отсутствующего/неподтверждённого номера.
- Проверка здоровья API больше не требует таблицу SMS-кодов и не зависит от настройки TextBee.
- Двухфакторная аутентификация необязательна: пользователь может включить её, а для отключения требуется действующий код аутентификатора. Если 2FA включена, вход по-прежнему проходит через challenge.
- Исправлен параметр срока жизни токена в `PCLoginRepository::issueToken()`, где ранее использовалась неинициализированная переменная.
- Обновлены проверки функций под новый сценарий без телефона.

## Файлы, которые нужно заменить

Скачай ZIP этого репозитория и замени на хостинге только эти файлы, сохраняя структуру каталогов:

1. `bootstrap.php`
2. `public/index.php`
3. `register/api/Controller.php`
4. `register/validators/RegistrationValidator.php`
5. `register/services/RegistrationService.php`
6. `register/repositories/RegistrationRepository.php`
7. `login/services/LoginService.php`
8. `login/repositories/LoginRepository.php`
9. `profile/api/Controller.php`
10. `security/api/Controller.php`
11. `security/services/TwoFactorService.php`
12. `tests/check-features.php` (нужно только для проверки кода; в рабочем API не участвует)

**Не удаляй остальные каталоги и файлы сервера.** Этот репозиторий содержит только изменённые файлы, поэтому скачивание ZIP не заменяет весь сервер.

## Перед заменой

1. Сделай резервную копию перечисленных файлов на хостинге.
2. Убедись, что `config.php` остаётся на сервере и содержит актуальный пароль БД. Этот файл не входит в репозиторий.
3. Не удаляй столбцы `phone` и `phone_verified_at` и таблицу `phone_verification_codes`: они могут существовать в старой схеме, но эти исправления больше не требуют их для регистрации и входа.
4. SQL-миграция для этого патча не нужна: схема проекта допускает `users.phone = NULL`.

## Проверка после установки

Открой:

- `https://плюсчат.рф/api/v1/health` — ожидается HTTP 200 и JSON с `"ok": true`, `"database": "connected"`, `"schema": "ready"`.
- `https://плюсчат.рф/` — ожидается JSON со статусом `online`.

Затем проверь через приложение:

1. Зарегистрируйся только с email, паролем и обязательным именем.
2. Получи шестизначный код по email и подтверди почту.
3. Войди по email и паролю — телефон и SMS не должны запрашиваться.
4. Заверши профиль, выбрав уникальный ник.
5. Открой список чатов и профиль; проверь, что запросы с Bearer-токеном проходят.
6. Если у аккаунта ранее включена 2FA, введи код аутентификатора после пароля.

Если проверка `/api/v1/health` возвращает 503, посмотри серверный PHP error log и JSON-ответ: это обычно указывает на пароль/доступ к БД или недостающие таблицы. Не публикуй пароль БД, токены, API-ключи и содержимое `config.php`.

## Важные замечания

- Патч не меняет домен и не добавляет шлюз или прокси.
- Реальные секреты, пароль БД и ключи TextBee не хранятся в Git.
- Старые SMS-таблицы могут оставаться в БД; это не мешает входу без номера телефона.
